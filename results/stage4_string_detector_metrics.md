## 읽는 법

**Epoch 28이 최고 성능** (F1 0.7333, Precision 0.8684, Recall 0.6346, Avg IoU 0.8732).
앙상블에는 이 체크포인트를 썼다.

기록에서 눈에 띄는 점:

1. **Precision은 초반부터 높은데 Recall이 바닥이다.** 1에폭에서 이미
   Precision 0.32 / Recall 0.05다. 모델이 "확신할 때만 드물게 예측하는" 쪽으로
   먼저 수렴했다는 뜻이다. 결함이 512x512 안에서 11px짜리 하나뿐이라 아무것도
   예측하지 않는 것이 손실 관점에서 안전한 선택이기 때문이다.

2. **Recall이 0.05에서 0.63까지 오르는 것이 학습의 대부분이다.** 7에폭(0.25),
   13에폭(0.54), 22에폭(0.61), 28에폭(0.63)으로 계단식으로 올라간다.

3. **Average IoU는 처음부터 0.80대로 거의 변하지 않는다.** 일단 잡기만 하면
   위치는 정확했다는 뜻이다. 즉 이 문제의 어려움은 "정확히 어디인가"가 아니라
   **"있다는 걸 알아채는가"**에 있었다.

4. **13→14, 18→19, 22→23처럼 F1이 크게 출렁인다.** 검증셋 `st` 결함이 312개뿐이라
   TP 몇 개 차이로 Recall이 크게 흔들린다. 그래서 "최고 F1 에폭"을 고르는 것 자체가
   과적합일 수 있다 — 이 부분은 나중에 개선한다면 여러 시드로 재현성부터 확인해야 한다.

## 주의: 이 수치를 정리본과 직접 비교하지 말 것

이 표는 원본 평가 코드로 측정한 값이다. 정리본(`src/seaweed/metrics.py`)은
아래 두 가지를 고쳤기 때문에 같은 체크포인트라도 수치가 달라진다.

- 신뢰도 임계값 미달 예측을 FP로 세던 것 → 세지 않도록 수정 (Precision이 올라감)
- 예측 하나가 여러 GT와 겹칠 때 IoU를 중복 누적하던 것 → 그리디 1:1 매칭

정리본으로 다시 측정하려면 체크포인트를 그대로 두고
`scripts/stage4_eval_ensemble.py`를 돌리면 된다.
